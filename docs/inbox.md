# 受信箱を測る（**段 1・自分のメールで動かす**）

> **相手が要りません。**P2P も会議も使わず、**自分の受信箱 1 つ**で動きます
> （`PRD §2` /`PRD §12-5`「切り分けは『P2P が要るか』で引く」）。
>
> **AI は資格情報を作らない・置かない・貼らない**（baseline §14）。値を入れるのは人です。
> **実測値の記入も人が行います**（baseline §19 / §29）。AI は代筆しません。

---

## これは何をするか

受信箱を 1 回ぶん読んで、**今日、人間が判断することだけ**を出します。

- **本文は 1 文字も表示しません。**出るのは metadata（差出人・種別・要判断か）だけ
- **AI を呼びません。**規則で判定できるものは、モデルに渡しません（**D19**〜**D23**）
- **token の会計を書き足します。**「AI を呼ばないと、どれだけ減るか」を実測するためです

**メールを変更しません。**返信・削除・既読を付ける口を持っていません（`BODY.PEEK[]`・**D23**）。

---

## 0. まずつなぐ（`warifu mail`・0.1.44）

**パスワードをファイルに書かずに**つなぐ形です。ふだんはこちらを使います。

```bash
warifu mail add <メールアドレス> --host imap.gmail.com   # Gmail のアドレスなら --host は要りません
```

- **パスワードは macOS がたずねます**（2 回）。打った字は画面に出ず、割符を通らずにキーチェーンへ置かれます。
  引数には書かないでください（シェルの履歴に残ります）
- Google のアカウントなら、**アプリ パスワード**（16 字）を入れます（2 段階認証を有効にしてから作ります）
- 置いたあと、そのままつないで確かめます。出るのは**受信箱の通の数と未読の数だけ**です（件名も本文も出ません）

```
つながりました（読むだけ・imap.gmail.com）。受信箱 1234 通、うち未読 5 通
```

| | |
|---|---|
| `warifu mail list` | 控えたアドレスを並べる（つながない） |
| `warifu mail check [<アドレス>]` | もう一度つないで、数だけを出す（アドレスを省けば控えた全部） |
| `warifu mail sort [<アドレス>] [--last <通>]` | 新しいほうから（既定 200 通）**ヘッダだけ**を読み、札ごとの数と理由ごとの数を出す（0.1.45・下の「仕分け」）。差出人も件名も出さない |
| `warifu mail remove [<アドレス>]` | そのアドレスの控え（`mail.tsv` の 1 行）とキーチェーンの項目を消す（控えが 2 つ以上なら、アドレスが要る） |

**アドレスはいくつでも控えられます。**会社の受信箱と自分の受信箱、のように `warifu mail add` を繰り返します。
同じアドレスを add し直すと、繋ぎ先を置き換えます（パスワードも聞き直します）。

**読むだけです。**受信箱は `EXAMINE` で開き、既読の印も付けません。macOS と Windows（0.1.48）で使えます。

### 口の種類と、秘密の入れ方（0.1.45）

| 種類 | 読む | 送る | 控え方 |
|---|---|---|---|
| `gmail`（Google Workspace を含む） | IMAP | SMTP（0.1.46 から） | `warifu mail add <アドレス>`（gmail.com は繋ぎ先を決める。会社のドメインは `--host imap.gmail.com`） |
| `imap` | IMAP | — | `warifu mail add <アドレス> --host <IMAP のホスト>` |
| `resend` | — | API（0.1.46 から） | `warifu mail add <アドレス> --resend`（アドレスは送るときの From） |

エージェントも MCP の `mail_account_add` で控えられます（札 `mail.account`）。**パスワードと API キーは、どの道でもエージェントを通りません。**
入れるのは人で、道は 2 つです。

- 割符の画面の［メール］→［控えた口］→［秘密を入れる］。伏せ字の欄に打つと、macOS は `security` の標準入力だけを通ってキーチェーンに、Windows は資格情報マネージャーに置かれます（引数・記録・エージェントへの返りに載りません）
- ターミナルで `warifu mail secret <アドレス>`。macOS が直接たずねます（**Windows ではこの道はありません**。`warifu mail add` は控えだけを置き、画面の［秘密を入れる］へ案内します・0.1.48）

受信箱のパスワード（`warifu-mail`）と送る口の API キー（`warifu-resend`）は、キーチェーンの別の項目に置きます。
`warifu mail list` と画面は「秘密が入っているか」だけを出し、字は出しません。

### 新しい通の知らせ方（0.1.46）

割符の画面が受信箱を見張り、新しい通が来たら、この機械のエージェントへ知らせます。口ごとに知らせ方を選べます。

| 知らせ方 | 何を知らせるか |
|---|---|
| `important`（既定） | 受注・問い合わせ・請求・未分類・なりすまし疑いが来たときだけ。知らせ・広告・迷惑は数えるだけ |
| `all` | 新しい通をすべて |
| `none` | 見張らない（つながない） |

```bash
warifu mail add <アドレス> --host imap.gmail.com --notify all   # 控えるときに決める
warifu mail notify <アドレス> important                          # あとから変える
```

エージェントからは `mail_account_add` の `notify` で決めます。控え直しても、決めた知らせ方は変わりません。
知らせに載るのは札ごとの数だけです（「受注 1・問い合わせ 2」）。差出人と件名は載せません。

### 仕分け（0.1.45）

ヘッダだけから、AI を呼ばずに札を決めます（本文は読みません）。上の行ほど先に効きます。

| 札 | 決め方 |
|---|---|
| 迷惑 | 受け取ったサーバが `X-Spam-Flag: YES` を付けた |
| なりすまし疑い | **受け取ったサーバ自身が付けた** `Authentication-Results`（いちばん上で、付けたサーバの名が受け手と合うもの）で DMARC が fail、または SPF と DKIM がどちらも pass でない／表示名に本当の差出人と違うメールアドレスを書いている。受け手が分からない繋ぎ先（いまは Gmail 以外）では認証の結果を読まない |
| 請求 | 件名に請求・支払いの語（**差出人が書ける所なので候補**） |
| 受注・問い合わせ | 件名に注文・問い合わせの語。**自動で送られたものには付けない**（こちらが買った注文の知らせを受注にしない） |
| 知らせ | 差出人の番地が noreply など返信を受けないもの |
| 広告 | `List-Unsubscribe` がある・`Precedence: bulk` |
| 未分類 | どれにも当たらない（エージェントが見る） |

`sort` は最後に「認証の結果を読めた通」を出します。なりすまし疑いが 0 でも、ここが 0 なら「疑いが無い」とは言えません。

### 控えたあとに起きること（0.1.44）

- **エージェントが読める。**`warifu mcp` の `inbox_list` が、控えた全部のアドレスから新しい 20 通ずつを汲みます。出るのは送信元・種別・優先度・要判断と、画面の受信箱と同じ仕分けの札（ヘッダだけから付ける・末尾の列）だけで、本文は段ごとの札が要ります
- **割符が見張る。**画面を開いている間、5 分おきに受信箱の見出しだけを見て、新しい通が来たらこの機械のエージェントに「何通来たか」と札ごとの数だけを知らせます（差出人も件名も知らせに載せません。0.1.46 から口ごとに知らせ方を選べます —— 上の「新しい通の知らせ方」）

## 1. 値を入れる（測るときだけ・`.env`）

下の測り方（`--example inbox`）は、まだ `.env` から読みます。**`.env` にはパスワードが平文で入る**ので、
測り終えたら消してください。`warifu mail` の控えから読む形には、次の段で揃えます。

```bash
cp .env.example .env
```

`.env` を開いて、自分の受信箱の値を入れます。**`.env` はコミットされません。**

| 変数 | 何を入れるか |
|---|---|
| `WARIFU_IMAP_HOST` | 例: `imap.gmail.com` |
| `WARIFU_IMAP_PORT` | 省略すると `993` |
| `WARIFU_IMAP_USER` | メールアドレス |
| `WARIFU_IMAP_PASSWORD` | **アプリ用パスワード**（下記） |
| `WARIFU_IMAP_LIMIT` | 1 回に取り込む上限（省略すると 50） |
| `WARIFU_LEDGER` | 会計の書き足し先（省略すると `warifu-ledger.tsv`） |
| `WARIFU_RULES` | 承認済みの規則（省略すると `warifu-rules.tsv`。無ければ規則なしで進む） |

**Gmail / Outlook は通常のパスワードでは入れません。**アプリ用パスワードを発行してください。
2 段階認証を有効にしてから、アカウントの設定で「アプリ パスワード」を作ります。

## 2. 回す

```bash
set -a; . ./.env; set +a
cargo run -p warifu-imap --example inbox
```

出るもの（実際の形）——

```
承認済みの規則 0 件（warifu-rules.tsv）

── 今日、人間が判断すること ──
  invoice      billing@example.com
  開かない 43

取り込み 50 通 / 解釈器を呼んだ 0 回 / token 0 + 0
会計を書き足しました: warifu-ledger.tsv
```

**「開かない」が多いほど良い。**それが「AI を呼ばずに済んだ通数」です。

## 2-A. 規則を置く（**2 日目から効く**）

**規則が無いと、初日は全部 `unknown` で「開かない」が 0 になります。**
規則は「この差出人からのこの形は、こう扱う」を書いたもので、
**当たれば解釈器（AI）を呼びません。**それがこの層の目的です（**D19**〜**D23**）。

ひな型があります —— **`docs/rules.example.tsv`**。

```
規則	billing@example.com	invoice	High	要判断
目印	請求書
抽出	金額	合計	円
```

| 列 | |
|---|---|
| `規則` | 差出人 ／ 種別 ／ 重さ（`Low` `Normal` `High`）／ `要判断` か空 |
| `目印` | 本文に含まれていれば当たる文字列 |
| `抽出` | 名前 ／ この文字列の後 ／ この文字列まで（省略可） |

**自分の受信箱に合わせて書き換えてから**置いてください。

```bash
cp docs/rules.example.tsv warifu-rules.tsv
```

**規則は人が承認したものだけを置きます。**受け取った中身から自動で作って自動で当てる実装は
**書きません**（**D5**）。書いた時点で「送ってきた側が規則を決められる」ことになります。

**読めない行があると、そこで止まります。**黙って捨てません ——
捨てると、当たるはずの規則が静かに消えて、解釈器を呼び直すことになります。

## 3. 記録してほしいこと（**人が書く**）

`issues/007` の最後の完了条件は「**実際に自分の受信箱で 1 週間使い、token の実測値を人が記録した**」です。

1 日 1 回まわして、`warifu-ledger.tsv` を貯めてください。**1 週間ぶんが要ります。**

書いてほしいのはこの 3 つです。**AI が代筆しません。**

| | |
|---|---|
| **取り込み通数と「開かない」の比** | 規則がどれだけ効いたか |
| **判断が要ると出たのに、実は要らなかったもの** | 規則の作り直しに要ります。**件名ではなく差出人で書いてください** |
| **判断が要らないと出たのに、実は要ったもの** | **これが一番重い。**取りこぼしです |

## 4. うまくいかないとき

| 症状 | 見る所 |
|---|---|
| `WARIFU_IMAP_HOST が設定されていません` | `set -a; . ./.env; set +a` を打っていない。`.env` を `cargo` へ渡す一手間が要ります |
| 認証で落ちる | **通常のパスワードを入れていないか。**アプリ用パスワードが要ります |
| 0 通しか取れない | 未読が無い（`fetch_unseen` は**未読だけ**を見ます） |
| 種別が全部 `unknown` | 規則がまだありません。**それで正常**です。「2-A. 規則を置く」を見てください |
| 規則を置いたら止まる | **読めない行があります。**列の数が合っているか（規則 5 列 / 目印 2 列 / 抽出 4 列）。区切りは**タブ**です |

## 5. 実サーバで確かめたこと

`warifu-imap` の試験は**自分で書いた台本**を読ませています（**D23**）。実在のサーバでは、次を確かめました（0.1.45）。

- Gmail（Google Workspace）の受信箱に、アプリパスワードで読むだけで繋がる（`warifu mail check`）
- 新しい 200 通をヘッダだけで仕分け、認証の結果（Authentication-Results）を 200 通とも読める（`warifu mail sort`）
- 画面の受信箱で一覧を出し、1 通を文字だけで開ける（既読にならない）

ほかのサーバ（Gmail 以外の IMAP）は、まだ確かめていません。繋がらなかったら、エラーの全文を Issue に貼ってください。
