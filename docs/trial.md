# 試験運用の手順（**2026-09-08 現在の版**）

> **これは AI が作りきった所までの引き渡しである。**
> ここから先は、実物を触った人にしか分からない（product-baseline §29）。
>
> **合否や気づいた点は、触った人が自分の言葉で書く。**
> AI に要約させない（§19 / §27）。要約した時点で、本当に困っていた所が落ちる。

## 1. 動かす

2 台要る。**同じ Wi-Fi につないでおく。**

> **Windows でも建ちます**（2026-09-07 に通った・**D40 は解消**）。
> `.msi` / `.exe` / `warifu.exe`（CLI）が出ます。入れ方は `docs/install.md`。
> **署名していないので、初回だけ「詳細情報 → 実行」が要ります。**

```bash
git clone https://github.com/meta-taro/warifu.git
cd warifu
scripts/setup-hooks.sh     # clone ごとに 1 回
pnpm install
pnpm --filter @warifu/desktop tauri dev
```

初回は依存を建てるので数分かかる。

### 許可を毎回聞かれるのを止める（macOS）— **建てる人だけの作業**

> **受け取る側は何もしない。**署名は `.app` の中に入って一緒に配られる。
> ここは**建てる人が 1 回やる**だけである。

**署名していないと、建て直すたびに別のアプリとして扱われる。**
macOS は署名でアプリを見分けて許可を覚えるので、**カメラ・マイク・ローカルネットワークの
許可を毎回聞かれる。**

手元の証明書で署名すれば止まる。**証明書の名前はここに書かない**（public リポジトリに
個人名を残さないため・baseline §25）。自分の環境で調べて渡す。

```bash
security find-identity -v -p codesigning     # 使える証明書を見る
export APPLE_SIGNING_IDENTITY="…"            # そのうち 1 つを選ぶ
pnpm --filter @warifu/desktop tauri build
```

**署名しない選択もある。**その場合は許可を毎回出すことになるが、動作は変わらない。

### 人に `.app` を渡すとき

**手元で使うのと、人に渡すのは別である。**

| 配り方 | 要るもの |
|---|---|
| 自分の Mac で建てて自分で使う | 何でもよい（署名なしでも動く） |
| **人に `.app` を渡す** | **Developer ID Application** の証明書 ＋ **公証**（notarize） |
| App Store / TestFlight | Apple Distribution の証明書 |

**Developer ID を持っていないと、受け取った側は Gatekeeper に止められる。**
右クリック →「開く」で回避はできるが、**渡すたびに説明が要る。**

Developer ID の発行は Apple の開発者アカウントでの作業で、**人にしかできない。**

> **`cargo run` では動かない**（2026-09-03 に踏んだ）。
> debug ビルドの Tauri は `devUrl`（`http://localhost:5173`）を読みに行くので、
> vite を一緒に起動しないと**窓が真っ白になる**。`tauri dev` が両方を面倒みる。
>
> 配布物として動かすなら `pnpm --filter @warifu/desktop tauri build`。

## 2. 触る順番

> **画面は 3 つの状態を持つ**（**D45**・2026-09-06）。
> 「会議をはじめる」を押すと、**したく・はじめる・入室する は引っ込み**、
> 会議キー（畳んだ形）・名簿・チャットが出る。会議が終わっても**会議前へは戻らない** ——
> 落ちた知らせとチャットが押し出されるためである。


**AI は画面を見られない。**ここに並んでいるのは、**触らないと分からないと分かった所**である
（2026-09-03 に、この手順で 10 件の不具合が出た）。

| | やること | 見てほしい所 |
|---|---|---|
| 1 | `warifu.app` を開く | **窓枠が自作か**（OS の白い帯が出ていないか）。ダークとライトの両方で |
| 2 | **帯を掴んで窓を動かす** | どこを掴んでも動くか。`─ ▢ ✕` が効くか |
| 3 | **メニューバーを開く** | 日本語か。`編集` に `貼り付け` があるか |
| 4 | **入力欄で右クリック** | 日本語か。`貼り付け` が効くか（効かなければ `⌘V` の案内が出るか） |
| 5 | `カメラとマイクを確かめる` を押す | **入る前に自分が映るか。**許可を断ったときの文言が、何をすればいいか分かる形か |
| 6 | マイク・カメラの入切を押す | **アイコンが状態で変わるか。**切なのに映っていないか |
| 7 | `会議をはじめる` を押す | 会議キーが出るか。**`コピーする` で取れるか** |
| 8 | **そのキーを自分に貼って** `入室する` | **落ちずに**「これは自分の会議キーです」と出るか |
| 9 | もう 1 台（または 2 窓目）に貼って `入室する` | 名簿が `2 / 12` になるか |
| 10 | **わざと 1 文字書き換えて貼る** | **繋がらないこと。**「割符として読めません」が出るか |
| 11 | 映像が出るのを待つ | **最初は音声だけ**で、経路が測れてから映像が出る（D29）。**何秒かかったか** |
| 12 | 経路バッジを見る | `不明` → `直接` へ変わるか。**跳ねていないか** |
| 13 | **窓を縦に縮める** | **帯が動かず、中身だけが動くか** |
| 14 | 片方を閉じる | もう片方に「経路が閉じました」が出るか |
| 15 | **自分の名前を押して、名前と紹介を書く** | 書けるか。**顔は自分と相手で必ず違う絵**になっているか |
| 16 | **顔の所に PNG を落とす** | 差し替わるか。**大きすぎる画像は断られるか**（理由が読めるか） |
| 17 | **ルームの行を押して、ルームに名前を付ける** | 一覧の名前も変わるか |
| 18 | **表示 → ライト / ダーク** | その場で切り替わるか。**印が移るか** |

## 2-B. **連絡帳から始める**（2026-09-07 から・**D57**）

**窓を開けると連絡帳が出る。**会議ではない。

```
┌──────┬─────────────┬──────────────────┬──────────────┐
│ 連絡帳│ この PC      │ 田中             │ 文字で話す    │
│  ルーム │  あなた      │ 公開鍵 4VKCVUB…  │              │
│  予定 │  図面くん zumen│ [チャットする]  │              │
│      │ 覚えている相手 │ [ルームに入れる]   │ [    ][送る] │
│      │  田中        │ [メールを送る]   │              │
└──────┴─────────────┴──────────────────┴──────────────┘
```

| | 見てほしい所 |
|---|---|
| **自分の名前を押す** | プロフィール（名前・短い紹介・顔）を書けるか。**顔は鍵から描かれる**ので、人ごとに必ず違う |
| **エージェントに名乗らせる** | `profile_set` で自分のエージェントを名乗れるか。**画面には「図面くん  zumen」と、名乗りとエージェントの両方が出る**か |
| **名前を押す** | 何ができるかが右に出るか。**押せない口は、なぜ押せないかが読めるか** |
| **鉛筆を押して呼び名を付ける** | 名前の隣の鉛筆 1 つだけ。**同じことをする口が 2 つ無いか** |
| **エージェント** | 起動すると**勝手に行が増えるか。**1 人ずつ並ぶか（`docs/mcp.md`） |
| **ルームの面へ移る** | 会議中に移っても**相手の声が消えないか**（ここは耳でしか確かめられない） |

### この PC のエージェントを、同じ会話につながらせる（**D55** / `docs/mcp.md`）

```bash
warifu setup            # Claude Code の利用者ごとの設定へ 1 回だけ入れる
```

**どのフォルダで立ち上げても `warifu` が出る。**既定は**会話と、自分のエージェントの名乗りだけ**（受信箱も予定表も許さない）。
エージェントが `chat_send` で言った行が、**そのまま人の画面に出る。**

**どこで動いているエージェントかが名前に出る**（`zumen の AI` など・D62）。
1 台で複数のエージェントがつながれるので、**まとめて 1 人にすると、どれが喋ったのか分からない。**

### 留守中でも届くようにする（**任意**・**D71** / `docs/relay.md`）

**割符はサーバーを 1 台も立てないので、相手が起動していなければ言葉は消える。**
届くようにしたいなら、**導入する側が預かり所を 1 台立てる。**

```bash
warifu relay --allow-file ~/warifu-allow.txt     # 使ってよい人の公開鍵を 1 行ずつ
```

出てきた宛先を、**ルームの面の「預かり所（任意）」に貼る。**

| | |
|---|---|
| 預かり所は**中身を読めない** | 封のまま持つ。開ける鍵を持っていない（D69） |
| **渡したら手放す** | 溜め込む場所にしない。7 日で捨てる |
| **名簿が空なら起動しない** | 誰でも使える中継にすると、**立てた人が知らない誰かの通信を運ぶ** |
| 留守中に届いた分 | 「**留守中**」の印と、**出した側の時刻**で並ぶ |

**まだ 1 台の中でしか通していない**（2026-09-08）。**2 台での確認は、ここでやってほしい所。**

## 2-A. **画面を使わずに確かめる**（CLI）

映像より先に、**そもそも 2 台がつながるか**を確かめたいときはこちら。
**人が画面を押す必要が無い**ので、離れた機械どうしでも、エージェントどうしでも回せる。

```bash
cargo build -p warifu-cli

# 待つ側（会議キーが標準出力の 1 行目に出る）
./target/debug/warifu host > /tmp/warifu.key 2>/tmp/warifu.log &
head -1 /tmp/warifu.key        # ← これを相手へ渡す

# 入る側
echo "こんにちは" | ./target/debug/warifu join '<会議キー>' --idle 30

# 待つ側で受け取ったもの（2 行目以降）
tail -n +2 /tmp/warifu.key
```

**`--ttl` は普段は要りません。**既定は 24 時間です
（2026-09-07 に 10 分から変えました —— **離エージェントしている間に切れて、再発行する手間が重かった**）。

**短くしたいときだけ指定します。**予定に紐づく会議なら `--from` / `--until` を使ってください。

**通れば、割符・戸口・会議・Intent の全部が通ったことになる。**映像はその上に載るだけ。

### 予定に紐づく会議キー（**D43**）

```bash
# 1 時間後に始まり、2 時間後に終わる鍵
warifu host --from +3600 --until +7200
```

**開始前に入ろうとすると断られる。**

```
warifu: まだ始まっていません
```

時刻は Unix 秒か `+<秒>`（いまから）。**人が読む日時は受けない** —— 時間帯の扱いを
間違えると「1 時間ずれた鍵」が黙って出るため。日時の UI は予定表の側の担当。

**開始前に誰かが押しても、主催は落ちない**（2026-09-04 に落ちていたのを直した）。

### 会議が終わったとき、主催の手元に出るもの

**「帰った」と「落ちた」は別の文言で出る**（2026-09-04 に分けた）。次の手が変わるため。

```
warifu: 相手が帰りました
```

相手が挨拶して閉じた。**会議はこれで終わり。**

```
（主催の手元）
warifu: 相手が落ちました（経路で落ちました: 受け取る途中で落ちました: connection lost）
warifu: 待ち直します。同じ相手だけが、14 分 18 秒のあいだ戻ってこられます

（入る側の手元）
warifu: 同じ会議キーで入り直せます（あと 14 分 18 秒）
```

回線が切れた・相手の機械が落ちた。**同じ会議キーで戻ってこられる**（**D44**）。
**鍵を作り直さなくてよい。**

**戻れるのは、さっきまで入っていた同じ相手だけである。**別人が同じ鍵で入ろうとすると、
主催の手元にこう出る（相手には返さない・D31）——

```
warifu: 通しませんでした（その会議キーで入っていた相手ではありません）。待ち直します
```

**会議キーの期限（`--ttl` / `--until`）は伸びない。**過ぎたら戻れない。

**気づくまで 30 秒ほどかかる**（実測 33 秒）。相手が挨拶せずに消えた場合、
QUIC が「居なくなった」と判断するまでの時間である。**その間は待っていてよい。**

> **回線が一瞬切れただけでも会議が終わる。**これは分かっていて残している制限で、
> 直すには D12（割符の一回性）を触ることになる。案は `issues/009` に書いた。

### 3 人以上でやる（**三者会議**）

**会議キーは 1 本につき 1 人**である（割符は「1 つの鍵 = 1 人」・**D12**）。
3 人目を呼ぶなら、鍵のカードの「**会議キーをもう 1 本出す**」を押して、その人に渡す。
**前の鍵は使えたままである。**

```
名簿 3/12 / 相手 2 人
```

**文字は全員へ回る**（**D48**）。参加者どうしは繋がっていないので、
**主催が聞いた文字をほかの人へ配る。**言った人はそのまま載る。

```
（B が喋ると、C の手元に）AOYAC23WLUH5…: B です。C さん、聞こえますか。
```

**カメラは要らない。**1 台でも `WARIFU_HOME` を分ければ 3 人ぶん試せる。

```bash
WARIFU_HOME=/tmp/w-b warifu join '<1 本目>'
WARIFU_HOME=/tmp/w-c warifu join '<2 本目>'
```

### 画面を使わず、エージェントだけで（**D50**）

**CLI の主催も複数人を受ける。**`--keys` で人数ぶん出す。

```bash
warifu host --keys 2          # 会議キーが 2 本、標準出力に出る
```

**実測（2026-09-06・1 台の中）** —— 3 名で 60 通、**全部届いて中央値 3.3 ms**。
主催が中継する向き（B → C）も、中継しない向きと差が出ていない。

**これは 1 台の中の数字である。**別の機械どうしでは網の往復がこれを大きく上回る。
**3 台で測るのは人の工程。**

### 相手を覚える（画面でも CLI でも）

**画面**: 名簿の行の「名前を付ける」を押して、呼び名を入れて「決める」。
空にすると忘れる。**自分の行には出ない。**

付けた名前は、**名簿・映像の見出し・チャットの差出人**に出る。
CLI と同じ置き場所（`contacts.tsv`）なので、**どちらで付けても両方で効く**（**D46**）。

```
名簿      Mac Air のエージェント   不明   [名前を付ける]
チャット  Mac Air のエージェント  こちら Mac Air のエージェントです。
```

**別の機械のエージェントと文字で話すときは、先に名前を付けておく。**
鍵の頭（`67R54JO7ND6P…`）だけでは、人なのかエージェントなのかも分からない。

### CLI から覚える

```bash
warifu id                              # 自分の公開鍵（閉じても変わらない）
warifu host --remember "Mac Air"       # つながった相手を、その呼び名で覚える
warifu contacts                        # 覚えた相手を並べる
warifu contacts forget "Mac Air"       # 忘れる
```

2 回目からは「知らない相手（BJTFT46R…）」ではなく**呼び名で出る。**

**覚えても、会議キーは要る。**覚えているのは**誰か**であって、**いまどこに居るか**では
ないため（住所は会議キーに入っている）。ここは `issues/009` の会場鍵で埋める予定。

### **1 台で 2 人を試すとき**

**身元がこの端末に 1 つになった**（D42）ので、同じ機械で `host` と `join` を
そのまま動かすと**自分自身を招くことになり、断られる。**
`WARIFU_HOME` で置き場所を分ける。

```bash
WARIFU_HOME=/tmp/warifu-a warifu host --ttl 300 > /tmp/a.key &
WARIFU_HOME=/tmp/warifu-b warifu join "$(head -1 /tmp/a.key)"
```

**画面（`warifu.app`）と CLI は同じ身元になる。**別人として試したいときも同じように分ける。

> **映像は扱わない。**CLI が運ぶのは文字だけである。

## 3. 特に判断してほしいこと

**AI では決められない所である。**

1. **経路バッジの出し方と、映像が出るまでの間** — `直接` / `中継` / `不明` の 3 つで足りるか。
   「直接」を名乗るまで 3 回待ち、**測れるまで映像を流さない**作りにしてある（D29）。
   **待たされている感じがするか。**ここは体感でしか判断できない
2. **会議キーの渡し方** — テキストの貼り付けで運用に耐えるか。QR が要るか、紙で足りるか
   （有効期間は 2026-09-07 に 24 時間へ延ばした）
3. **覚えた相手の呼び名** — こちらが付ける形にしてある（相手の名乗りを信じない）。
   **`warifu contacts` の並びと文言で足りるか。**画面側にはまだ出していない

## 5-A. ログは自動で残ります（**2026-09-07 から**）

**アイコンから起動しても残ります。**置き場所はここです。

```
~/Library/Application Support/warifu/warifu.log
```

**前の分を消しません。**追記で足していきます —— **前回落ちた理由が消えると、追えなくなる**ためです。

**中身は要所だけ**で、**会議の文字も鍵も住所も書きません。**

それまでは、こちらが `> warifu.log` を付けて起動したときしか残っていませんでした。
**人が普通に使って不具合を踏んでも、見に行ける記録が無かった**ということです。

## 5-B. ログを画面に出しながら起動する（**繋がらなかったときに効く**）

`open` や Finder から起動すると、**アプリの言うことがどこにも残らない。**
システムログには WebKit の内部メッセージしか出ず、経路の話は 1 行も無い。

**ターミナルから起動すると、そのまま取れる。**

```bash
~/Desktop/warifu.app/Contents/MacOS/warifu-desktop > ~/Desktop/warifu.log 2>&1
```

出るのは経路の要所だけ。**秘密情報は書かない**（割符の中身・SDP の中身・鍵の全桁は出さず、
種類と長さと先頭 12 文字だけ）。**そのまま人へ見せてよい。**

```
[warifu] 入室: 会議キーを読んだ（宛先 WARIFU1-ABCD…）
[warifu] 入室: 経路がつながった（相手 …）
[warifu] 待受: 割符は合った
[warifu] 受信: 下ごしらえ（SDP / ICE）
[warifu] 画面: 相手の映像が届いた（…）
```

**どこまで進んだかが分かる。**とくに `下ごしらえが来た … ← **通話が無い**` は、
2026-09-04 に実際に起きた不具合（呼んだ側で通話が作られていなかった）の形である。

> **起動し直すと、いまの会議キーは消える。**身元は残る（D42）。
> 試験を始める前にやること。

## 6. 動かないときに見る所

| 症状 | 見る所 |
|---|---|
| **繋がらない** | 同じ Wi-Fi か。**外部 STUN を使っていない**ので、網が分かれていると繋がらない |
| **繋いでも何も起きない** | 会議キーが切れていないか（24 時間）。**割符が合わない相手は黙って落とす**（D31・断る理由を返さない） |
| **会議中に相手が消えた** | 30 秒ほど待つ（QUIC が気づくまで・実測 32〜33 秒）。`相手が落ちました` のあと、**主催は待ち直す**。相手は**同じ会議キーで入り直せる**（D44）。鍵の作り直しは要らない |
| **`warifu host` が終わらない** | 2026-09-04 に直した（標準入力の読み取りを待って畳めていなかった）。古いビルドが残っていないか |
| **映像が出ない／片方だけ出る** | offer を出すのは一方だけ（**D38**）。両方から出ていたら、それは不具合である |
| **経路バッジが `不明` のまま** | `RTCStatsReport` の形が想定と違う可能性がある。**`path.ts` は実機で一度も確かめていない** |
| **カメラ・マイクが使えない** | 許可を断っていないか。**2026-09-04 より前の版には使用目的の記述が無く、macOS が渡さなかった**（`Info.plist`）。古い `.app` を消して入れ直す |
| **相手が見つからない・繋がらない** | **ローカルネットワークの許可**を出しているか。warifu は外部の中継を使わないので、**断ると何も繋がらない** |
| **窓が真っ白** | `cargo run` で動かしていないか（debug は `devUrl` を読みに行く）。`.app` か `tauri dev` を使う。それでも白いなら CSP の `script-src` を疑う（2026-09-03 に踏んだ） |
| **窓が動かない・メニューが英語・右クリックが英語** | いずれも 2026-09-03 に直した。**古い `.app` が残っていないか**（デスクトップのものを入れ替える） |
