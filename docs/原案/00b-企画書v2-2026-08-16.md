# AI-Native P2P Trust Network 企画書

## Human / Device / AI Agent が同じ信頼ネットワークでつながるOSS

**Status:** Project Draft\
**Date:** 2026-08-16

## 1. 概要

単なるP2PチャットやWeb会議アプリではなく、**Human / Device / AI
Agentを第一級のIdentityとして扱い、Identity・Trust・Permission・CommunicationをLocal-first
/ P2P-firstで統合するOSS通信基盤**を構築する。

Text / File / Voice / Videoに加え、AI
Agent同士が構造化Intentを交換し、カレンダー調整や業務処理を安全に実行できる世界を目指す。

中心思想は **Human同士のMessengerとAI Agent Networkを別世界にしない**
こと。

「AIがデバイスベースで自我を持つ」はChallenge Trackとし、MVPでは
Persistent Agent Identity（Identity / Memory / Relationships / Goals /
Permissions / History）として工学的に扱う。

## 2. なぜ作るのか

現在は電話番号→電話、メールアドレス→Email、SNS ID→SNS、Workspace
Account→社内Chat、Meeting URL→Video Conference、AI
Agent→各ベンダー独自環境、とIdentityと通信方式が分断されている。

AIがDevice上で継続的に仕事をするなら、Human / Device /
AgentのIdentity、Connection、Trust、Capability、Profile、Actionを統一的に扱える基盤が必要になる。

## 3. 位置付け

目標は Another Messenger ではない。

## 4. 既存OSS・標準の調査

### SimpleX Chat

E2EE
Messaging、File、Voice/Video、招待型Connection、Spam耐性などが近い。Human向けSecure
Messengerとして成熟しており、Privacy / Connection UX /
E2EEは再発明しない。

### Jami

分散P2P Communication、Text、Voice、Video、File、Conference、Device
Identity、SIP等が近い。P2P Voice/VideoとDistributed
Communicationの先行例として調査する。

### Nostr

Public Key Identity、Signed Event、分散Relay、Vendor-independent
Protocolが参考になる。純粋P2PではなくRelay型であり、Identity
portabilityとProtocol simplicityを学ぶ。

### OpenMolt Network

P2P Agent-to-Agent、libp2p、DHT、DID、QUIC/Noise、Agent
Task、Pub/Sub等が今回にかなり近い。P2P Agent
Networkそのものを再発明せず、OpenMolt/libp2pをBuilding
Block候補として精査する。

### Agent Identity Protocol (AIP)

DID、Agent Identity、Capability-based Authorization、Cryptographic
Delegation等の標準化提案。Agent
Identity/Capabilityを独自仕様化する前に標準化動向を確認する。

### Signet AI

Local-first Agent Identity、Persistent
Memory、Secrets、Transcript等がPersistent Agent Identity構想に近い。

### OpenAgents

Human + AI Agent Collaboration、Workspace、Channel、DM、Local Agent
execution等が近い。ただし本企画はWorkspaceよりIdentity / Trust / P2P
Communication Layerを中心に置く。

## 5. 独自性

個別技術ではなく、**HumanとAI Agentを同じTrust
Graphに載せる統合思想**を差別化点とする。

``` text
Personal Profile
├ Family / Friends       Human
├ Personal Agent         AI
└ Trusted External Agent AI

Work Profile
├ Employees              Human
├ Customers              Human
├ Work Agent             AI
├ Customer Agent         AI
└ Organization Policy
```

同じConnectionからText / File / Voice / Video / Calendar / Meeting /
Task / Agent Request / Business Actionへ進める。

## 6. 設計原則

-   Local-first
-   P2P-first, not P2P-only
-   E2EE
-   No Invisible Participant
-   Explicit Trust
-   Transport interchangeable
-   AIにRoot権限を与えない
-   SecurityをAI判定だけに依存しない

Authentication / Trust / Permissionを分離する。

``` text
Authentication = 誰であるか
Trust          = どの程度信用するか
Permission     = 何を許可するか
```

## 7. Identity

Email/電話番号をRoot Identityにしない。

``` text
Identity
├ Public Key / DID
├ Type: Human / Agent / Organization
├ Devices
├ Aliases: Email / Phone / External Account
└ Connections
```

各Deviceは独立Keyを持ち、紛失時はDevice単位でRevokeする。

## 8. Personal / Work Profile

Google Accountのように明確にProfileを切り替える。

``` text
Application
├ Personal
├ Company
├ Client A
└ + Add Profile
```

ProfileごとにIdentity/Keys、Trust Graph、Messages、Files、Agent、Agent
Memory、Permissions、PoliciesをIsolationする。

Personalは本人管理。WorkはOrganization発行・管理。退職時はWork
ProfileのみRevokeする。

## 9. First Connection UX

``` text
Install
 ↓
Create Personal Identity
 ↓
First Connection
 ├ Show QR
 ├ Scan QR
 ├ Invite Link
 ├ Contactsから候補
 └ Join Organization
```

公開User
Directoryを中心にしない。ContactsはTrustそのものではなくConnection候補/Trust
Evidenceとして扱う。

## 10. Trust Graph / Trust Evidence

中央SNSのFriend GraphではなくProfile所有のLocal Trust Graph。

外部Contacts、GitHub、Organization
Directory、CRM、QR/NFC、過去Connection等からTrust
EvidenceをImportできるが、外部Accountだけで自動的に最高Trustへ昇格させない。

## 11. Spam / Abuse Defense

UnknownはConnection Requestから開始。Rate Limit、Challenge、Trust
Evidence、Mutual Connection、AI Classification等を組み合わせる。

Unknownから大容量File、Voice/Video、Agent
Command、Automation、Executable等は原則禁止する。

## 12. File Security

受信Fileを直接Downloadsへ保存せずQuarantineへ入れる。

``` text
Incoming File
 ↓
Quarantine
 ↓
MIME / Extension / Hash
Malware Scan
Archive Inspection
Organization Policy
Optional Sandbox
 ↓
ALLOW / BLOCK / REVIEW
```

Trusted IdentityからのFileもZero
Trustで検査する。Agentは未検査Fileを実行できない。

## 13. P2P / Voice / Video

1対1WebRTC P2Pは実用領域。Small
GroupはMesh可能だが人数増加でUpload負荷が増える。Large
ConferenceはSFUが合理的。

品質を犠牲にして完全P2Pに固執せず、Serverを信用しなくても成立する設計を目指す。

## 14. Embedded SFU / Cooperative P2P

Desktop App自身が必要に応じてSFU/Relay Nodeになる。

``` text
Desktop App
├ Identity
├ P2P Client
├ WebRTC
├ Embedded SFU / Relay
├ Trust Graph
├ Agent
└ Topology Manager
```

回線・CPU・Battery等に余裕のあるDesktopを自動選出し、退出/劣化時には別PeerへFailoverする。

将来的には複数Peerによる分散Relay Treeも研究する。

``` text
        A
      /        B     C
    / \   /    D   E F   G
```

Relay CapabilityにはBandwidth、Latency、CPU、Memory、Battery、Network
Type、Reliability、Willingnessを含める。

Fallback:

``` text
Direct P2P
 ↓
Peer Embedded SFU / Relay
 ↓
Other Peer Failover
 ↓
Community / Company Relay
 ↓
Public TURN / SFU
```

## 15. Agent Identity / Capability

``` text
Agent
├ Agent ID
├ Public Key
├ Owner
├ Device
├ Runtime / Model
├ Capabilities
├ Memory
└ History
```

AgentにはCapabilityを明示する。

例：Read/Summarize/Draft/Calendar Queryは許可、External SendやCalendar
CreateはApproval、Device追加・Root Trust変更・Audit
Policy変更・未検査File実行は禁止。

## 16. Agent-to-Agent Protocol

Human向け自然言語だけでなく構造化Intentを交換する。

候補：

-   message.\*
-   meeting.\*
-   calendar.\*
-   file.\*
-   contact.\*
-   task.\*
-   quotation.\*
-   invoice.\*
-   notification.\*

特定LLMベンダーのFunction Calling仕様をProtocolにしない。

## 17. 初期代表Demo --- AI会議調整


## 18. Organization Extension

会社はWork ProfileについてMember、Allowed Connections、External
Allowlist、File Policy、Voice/Video Policy、Agent Policy、Device
Policy、Retention、Auditを設定可能。

「会社指定の相手以外とはWork Identityで接続できない」を実現する。

## 19. Organization Audit

企業Profileでは必要に応じCompliance
Archiveを利用できる。ただし秘密Backdoorにはしない。

復号能力を持つHuman / Agent / Organization
AuditorはすべてIdentityとして明示する（No Invisible Participant）。

Audit accessにはRole、Reason、Scope、Approval、Immutable Audit
Logを持たせる。

## 20. P2Pと法務

P2P技術そのものを違法技術として扱わない。Winny事件の教訓から、Public
Piracy File Index、Unlimited Anonymous
DM、違法利用を価値とする機能等は作らない。

本プロジェクトはOSSコード公開が中心。

将来Public Relay/TURN/SFU/Telephone
Gateway等を運営主体として提供する場合は、日本の電気通信事業法、通信の秘密、個人情報保護、著作権等について専門家レビューを行う。

## 21. md-business / 連動くんとの関係

独立OSSとする。

``` text
                 Trust Network
                      │
                  Agent Layer
        ┌─────────────┼─────────────┐
   md-business      連動くん       Other OSS
   Documents        Web Actions
```

md-businessはQuotation/Invoice/Document等のAdapter、連動くんは許可された外部Web操作のExecution
Adapterになり得る。本OSSは両者を必須Dependencyにしない。

## 29. Project Vision

``` text
Human ─ Device ─ Agent
   \       |       /
        Trust
          |
Human ─ Device ─ Agent
          |
        Trust
          |
      Community
          |
        World
```

Humanは複数の社会的Profileを持ち、DeviceとAI
Agentにも継続的Identityがある。HumanとAgentは信頼できる相手を選び、必要な情報だけを交換し、必要なActionだけを許可する。

Desktopは単なるClientではなく、必要に応じ通信Networkを支えるNodeにもなる。

> **多数のHuman・Device・AI
> Agentが、小さな信頼関係と余剰Resourceを持ち寄り、分散して協働する。**

そのためのIdentity / Trust / Communication LayerをOSSとして構築する。

## 30. 立ち上げ判断

**GO**

ただし、P2P Messenger、Agent Network、Agent
Identity、暗号、Codec等の既存技術を再発明しない。既存OSSを競合だけでなくBuilding
Blockとして扱い、Security / Threat
Modelを後付けにせず、AIの「自我」はMVP要件にしない。

本プロジェクトの価値は、**P2P、Identity、Local AI、Agent
Protocol、E2EE、Organization Policyを、人間とAIが共存する一つのTrust
Networkとして統合すること**にある。
