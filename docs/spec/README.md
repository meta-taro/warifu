# docs/spec —— あるべき形

割符が**どう振る舞うべきか**を、人が見て一目で確かめられる文で書く。
実物がこのとおりでなければ、**実物が間違っている**（文書を実物に合わせて直すときは、理由を同じ commit に書く）。

| 文書 | 何を決めるか |
|---|---|
| [00-用語と仕切り](00-用語と仕切り.md) | 誰が、どこで、誰に向けて話すか。言葉の対応 |
| [01-ルーム](01-ルーム.md) | 主催・名簿・配り・戻り方 |
| [02-会話](02-会話.md) | 番号・届き・未読・下書き・残す |
| [04-MCP と画面の連動](04-MCPと画面の連動.md) | エージェントが見るものと人が見るものは同じ。自己点検・版の約束 |
| [05-更新と配布](05-更新と配布.md) | 版の単位・新しい版に気づく・入れ替える・互換・版ごとの説明・配ったあと |
| [invariants.tsv](invariants.tsv) | 1 条ごとに、**どの試験が守っているか**。空の行は未担保 |

書く順は 03（会議）・06（中継）・07（メール）・08（画面の受け入れ基準）。

## 書き方

- 1 条 1 文。番号（`S<文書>-<n>`）を付ける。番号は振り直さない（消すときは「廃止」と書いて残す）
- **人が確かめられる形**で書く（「見出しの人数 ＝ 相手の数 ＋ 1」）。実装の都合は書かない
- 不具合を直したら、守る条を `invariants.tsv` に足す。**再現する試験を先に書く**（RED → GREEN）
- 会話・人の名前・機械の呼び名・網の詳細は書かない（このリポジトリは公開）
