## 1. シェルの変数名は ASCII だけ

コメントも、文字列も、日本語で書いてよい。**変数名だけは書けない。**

```bash
前=$(git describe ...)     # → 前=v0.1.0-alpha.15: command not found
prev=$(git describe ...)   # ○
```

**2026-09-10 に 2 度、2026-09-13 に 3 度目を踏んだ。**
1 度目は commit の本文を組むところ、2 度目は `release.yml` の中、
3 度目は**見張りのスクリプト**である（`いま=13: command not found`）。

**3 度目がいちばん悪かった** —— スクリプトは動いているように見え、
**「Issue に動きが無い」と読めてしまった。**壊れ方が「黙って動かない」なので気づけない。

`.rs` / `.ts` の識別子は日本語で書ける（そう書いている）。**シェルだけが違う。**

### 同じ日に踏んだ親戚

**空白は、どの言語でも識別子に入れられない。**

```rust
fn 見比べる(場所: &Path, 画面の版: &str, cli の出力: &str)   // ← 空白。通らない
```

```ts
const WINDOWS の直し方 = [...]   // ← 空白。通らない
```

**日本語で書けることと、空白が入れられることは別である。**
**Rust の関数名は数字で始められない**（`fn 0_を言えば…` も落ちた）。

### `gh issue comment --body` も同じ

**2026-09-15 に踏んだ。**`--body "… `記録の版 2` が出ない …"` と書いて、
**バッククォートの中が実行され、その部分が投稿から消えた。**

**`--body-file` と heredoc で渡す。**

```bash

MD

```

#### **値を差し込みたくなったとき、同じ穴が開き直す**（2026-09-17）

**heredoc のクォートを外した瞬間に、バッククォートが戻ってくる。**

```bash

鍵: $(cat air.key)
```

## 6. **静的な棚を測る試験は、錠を持たせる**（並んで走ると混ざる）

Rust の試験は**既定で並んで走る。**`static Mutex<Vec<…>>` のような
**プロセスに 1 つしか無い棚**を、複数の試験が触ると**互いの値を見る。**

```rust
#[test]
fn 発言でない行は控えない() {
    let 前 = 直近の発言.lock()….len();   // ← ここで 0
    控える(&FromDesk::Joined { … });      //    隣の試験が 200 本積んだ
    assert_eq!(…len(), 前);              // ← left: 200 / right: 0
}
```

**2026-09-17 に踏んだ。**壊れ方が悪い —— **`控える` は正しく動いている。
落ちたのは測る側が並んでいたからで、失敗の文面は実装のバグに見える。**

**錠を 1 本置いて、棚を空にしてから測る。**

```rust
static 発言の順番: Mutex<()> = Mutex::new(());

fn 発言も一つずつ() -> std::sync::MutexGuard<'static, ()> {
    let 番 = 発言の順番.lock().unwrap_or_else(std::sync::PoisonError::into_inner);
    直近の発言.lock().unwrap_or_else(std::sync::PoisonError::into_inner).clear();
    番
}
```

**棚ごとに別の錠にする**（同じ錠にすると、関係の無い試験どうしが待ち合う）。
**毒された錠は `into_inner` で受ける** —— 先に落ちた試験のせいで、後続が
「錠が毒されている」で全部落ちるのを防ぐ（失敗が 1 本のとき 1 本だけ落ちてほしい）。

### 同じ根の親戚（**2026-09-16**）

**固定した socket のパスも、プロセスに 1 つしか無いもの**である。
`cargo test` を 2 本同時に回すと `AddrInUse` で落ちた ——

### 切り方

**走りの頭は、必ずこの行である。**

```

```

**`+秒` は起動からの経過**なので、**数字が小さくなった所が新しい走りの頭**である。


### **本物の束を 1 つ、試験に置く**（2026-09-18・Mac Air の提案）

> **手で作った束だけだと、在らない項目を自分で足せてしまいます。**
> **本物の束が 1 つ在れば、`totalAudioEnergy` が outbound に無いことが、その場で分かります。**

**マイクの許可を使わずに取れる。**

```js
const ac = new AudioContext();                       // **合成音。マイクを開かない**
const dest = ac.createMediaStreamDestination();
ac.createOscillator().connect(dest);
const a = new RTCPeerConnection(), b = new RTCPeerConnection();
// … a と b を互いに繋ぐ（ローカルのループバック）
a.addTrack(dest.stream.getAudioTracks()[0], dest.stream);
[...(await a.getStats()).values()]                   // ← **本物の束**
```

**測った結果**（engine: Chromium）——

```
outbound-rtp / audio    totalAudioEnergy   **無い**（undefined。0 ではない）
media-source / audio    totalAudioEnergy   **在る**（audioLevel・totalSamplesDuration も）
```
