## 1. シェルの変数名は ASCII だけ

コメントも、文字列も、日本語で書いてよい。**変数名だけは書けない。**

```bash
前=$(git describe ...)     # → 前=v0.1.0-alpha.15: command not found
prev=$(git describe ...)   # ○
```

**2026-09-10 に 2 度、2026-09-13 に 3 度目を踏んだ。**
1 度目は commit の本文を組むところ、2 度目は `release.yml` の中、
3 度目は**見張りのスクリプト**である（`いま=13: command not found`）。

**3 度目がいちばん悪かった** —— スクリプトは動いているように見え、
**「Issue に動きが無い」と読めてしまった。**壊れ方が「黙って動かない」なので気づけない。

`.rs` / `.ts` の識別子は日本語で書ける（そう書いている）。**シェルだけが違う。**

### 同じ日に踏んだ親戚

**空白は、どの言語でも識別子に入れられない。**

```rust
fn 見比べる(場所: &Path, 画面の版: &str, cli の出力: &str)   // ← 空白。通らない
```

```ts
const WINDOWS の直し方 = [...]   // ← 空白。通らない
```

**日本語で書けることと、空白が入れられることは別である。**
**Rust の関数名は数字で始められない**（`fn 0_を言えば…` も落ちた）。

### `gh issue comment --body` も同じ

**2026-09-15 に踏んだ。**`--body "… `記録の版 2` が出ない …"` と書いて、
**バッククォートの中が実行され、その部分が投稿から消えた。**

```
(eval):3: command not found: 記録の版
```

**投稿は成功してしまう**（欠けたまま）。**気づくのは相手が読んだ後**である。
**`--body-file` と heredoc で渡す。**

```bash
cat > /tmp/c.md <<'MD'
… `記録の版 2` …
MD
gh issue comment 19 --body-file /tmp/c.md
```

### Rust のモジュール名は**ファイル名になる**ので ASCII だけ

```rust
mod 候補;   // → error[E0754]: trying to load file for module `候補`
mod pick;   // ○（ファイルは pick.rs）
```

**2026-09-16 に踏んだ。**`.rs` の**中の識別子**は日本語で書けるが、
**モジュール名はファイル名に写る**ので書けない。

### 空白は、この日も踏んだ

**2026-09-16、4 度目。**`fn 重なったものは_1 つにする()` ——
**`_1` のあとに全角空白**が入っていた。

```
error: missing parameters for function definition
   fn 重なったものは_1 つにする() {
                       ^
```

**数字のあとに区切りを入れたくなると、空白を打つ。**そこが癖である。

### commit message も同じ

```bash
git commit -m "… `apps/desktop/…/+page.svelte` は …"   # ← バッククォートが走る
#   → command not found: +page.svelte（メッセージの一部が消える）
git commit -F - <<'MSG' …                               # ○ heredoc で渡す
```

## 2. Python を CI で回すなら、**読む所と出す所の両方**に文字コードを書く

日本語を扱うスクリプトを Windows の CI で回すと、**2 か所で落ちる。**

```python
# 読む —— text=True だけでは、その機械の既定（Windows は cp1252）で読む
subprocess.run([...], encoding="utf-8", errors="replace")

# 出す —— 標準出力も cp1252 なので、print で落ちる
for 口 in (sys.stdout, sys.stderr):
    if hasattr(口, "reconfigure"):
        口.reconfigure(encoding="utf-8", errors="replace")
```

**2026-09-10 に、この 2 つを別々のタグで踏んだ**（alpha.17 で読む所、alpha.18 で出す所）。
**片方だけ直して「直った」と思った**のが間抜けだった。

**手元で確かめられる。**

```bash
PYTHONIOENCODING=cp1252 python3 scripts/<名前>.py
```

**タグを打つ前にこれを回す。**CI で 1 往復するより速い。

## 3. まだ無い値を見る `if:` は、黙って段を飛ばす（**D99**）

GitHub Actions の段は上から走る。**`id:` を定義する段より前で `steps.<id>.outputs` を読むと、
条件は空文字と比べられて false になり、段ごと飛ぶ。しかも job は success になる。**

`scripts/check-step-order.py` が見ている（手元のゲートと CI の両方で走る）。

## 4. `spctl` はアプリの束を見る道具（**D101**）

単体の実行ファイルに当てると、**署名が正しくても rejected を返す**
（Apple 純正の `/usr/bin/env` ですらそうなる）。CLI は
`codesign --verify --strict` ＋ `TeamIdentifier` までで検める。

## 5. `cp` で実行ファイルを上書きしない

macOS は**そのパスの署名を覚えている**ので、中身だけ差し替えると
**`Killed: 9`（SIGKILL）**になる。**消してから置く。**

```bash
rm -f ~/.local/bin/warifu && cp <新しいもの> ~/.local/bin/warifu   # ○
```

2026-09-13 に踏んだ。**エラーは出ず、ただ黙って死ぬ**ので原因が分かりにくい。
