## Mac Air（`EKBN2GCQO35W…`）— 3 件

### 【1】自動更新が CLI を見ていない（**いちばん重い**）

> 案内は「アプリを終了して開き直すと更新の案内が出ます」でしたが、CLI（`~/.local/bin/warifu`）は
> 別バイナリで、そのままだと 0.1.2 のまま残ります。
>
> 今回の不具合は「画面と CLI が別の鍵を名乗る」ものなので、**アプリだけ上げた人は
> 直ったつもりで直っていません。**しかも症状は「繋がらない」だけなので、
> CLI が古いせいだと気づけません。

**そのとおりである。**D98 は画面と CLI の両方が新しくないと効かない。

やること（案）——

- 画面が**古い CLI を見つけて名指しで言う**（`~/.local/bin/warifu --version` を読む）
- 案内（`site/index.html`・`docs/`）に「**CLI も入れ直す**」を足す

### 【2】一致の確認を、人の目に任せている

> 52 文字の base32 を目で突き合わせるのは、まさに人が間違える所です。
> 頭と尻だけ見て「同じ」と言ってしまいます。
>
> CLI は画面と同じ置き場所を読めるので、`warifu id` か `warifu doctor` が
> 自分で突き合わせて「画面と同じです」「違います（画面が古い版です）」まで言えるはずです。

**そのとおりである。**こちらが出した確認手順（「目で見比べてください」）が悪い。

**2026-09-12 に直した** —— `warifu id` が自分で突き合わせて言う（`identity::見立てる`・試験 3 本）。
実物 ——

```
$ WARIFU_HOME=/tmp/別の身元 warifu id
warifu: 身元の置き場所 /tmp/別の身元
warifu: **この機械には身元が 2 つあります。**
warifu:   いま名乗る身元  S246YYBLEHTP…  /tmp/別の身元
warifu:   画面が使う身元  I3ILQUUJQHVS…  /Users/…/Library/Application Support/warifu
warifu: **画面と別人です。**WARIFU_HOME を外すと、画面と同じ身元になります
```

**画面をまだ開いていない機械では黙る**（「違います」と言わない。比べる相手が無いだけ）。

### 【3】`WARIFU_HOME` で黙って別人になる

> この機械には身元が 2 つありました。
>
>   `~/Library/Application Support/warifu` → `EKBN2GCQ…`（画面が使っている方）
>   `~/warifu-sshboard` → `HMRGLFLP…`（別の作業で作られた方）
>
> `WARIFU_HOME` を設定した手順書をなぞった人は、**自分が別人になったことに気づけません。**
> ルームキーは 1 本 = 1 人なので、ここで取り違えると 1 本無駄になります。

**`warifu id` が「この機械には身元が 2 つあります」と添える。**

**2026-09-12 に直した**（【2】と同じ口で言う）。
