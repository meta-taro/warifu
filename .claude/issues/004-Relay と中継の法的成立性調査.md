## これは何のための調査か

**「他人の通信を中継する」機能を、誰が・どの形でやるなら成立するのかを、一次情報で整理する。**

この企画は 2 か所で他人の通信を中継する:

| | どこ | 中継する主体 | 未決事項 |
|---|---|---|---|
| ① | 原案 §3.2 が許容する **Relay / Store-and-forward** | **自社**が立てたサーバー | `decisions.md` **D3** |
| ② | 企画書 v2 §14 の **Embedded SFU / Cooperative Relay** | **利用者の Desktop App** | `decisions.md` **D7** |

**②が本題。**①は「自社では Phase 2 まで運用しない」で先送りできるが、
**②は自社が何も運用しないのに中継が発生する**ため、先送りで回避できない。

**この Issue で結論（やる / やらない）は出さない。**決めるのはオーナー。
出してほしいのは**判断材料**であり、**特に「この構成なら届出が要らない」の条件**である。

---

## 前提（調査の出発点。ここは所与とする）

- 通信は **E2EE**。中継者は**中身を読めない**
- ただし中継者は **「誰と誰がいつ」＝メタデータには必然的に触れる**
- v2 §14 は Relay Capability に **`Willingness`**（中継の意思）を含めている
  ＝**利用者の同意を取る前提**で設計されている
- v2 §20 は「Public Piracy File Index を作らない」「Unlimited Anonymous DM を作らない」
  「違法利用を価値とする機能を作らない」を**既に非スコープとして宣言している**

---

## 調べる対象 — この 5 パターンを別々に判定する

**まとめて「P2P は合法か」を調べない。**構成ごとに答えが変わるので、必ず 5 つに分けること。

| # | 構成 | 中継するもの | 中継先 |
|---|---|---|---|
| **P1** | 自分の端末 2 台の間（PRD §2 の n=2） | 自分の通信のみ | 自分 |
| **P2** | 直接 P2P（1 対 1・中継なし） | なし | — |
| **P3** | **自社が立てた Relay / TURN** | 他人の通信 | 不特定 |
| **P4** | **利用者の端末が、自分の Trust Graph 内の相手だけを中継** | 他人の通信 | **既知の相手に限定** |
| **P5** | **利用者の端末が、不特定の Peer を中継**（v2 §14 の素直な読み） | 他人の通信 | 不特定 |

**P4 と P5 を分けるのが最大の目的。**
P4（信頼を設定した相手だけ中継する）なら Winny 型（不特定多数・匿名）とは構造が違うと
説明できる余地があるが、**中継可能な Peer が激減して v2 §14 の Fallback 設計と衝突する**。
**技術的な最適と法的な安全が逆を向いている**ため、どこで折り合うかの材料が要る。

---

## 各パターンについて出してほしいこと

### (1) 電気通信事業法上の位置づけ

- **電気通信役務にあたるか**（他人の通信を媒介しているか）
- **届出が必要か。不要ならその根拠**（条文番号 + 総務省の一次情報 URL）
- **事業者性が誰に生じるか** — 特に P4 / P5 で、**利用者本人**が何かを負うのか
- 「事業を営む」の解釈（無償・非営利・オープンソースの場合にどう扱われるか）

### (2) 通信の秘密

- 中継者が**メタデータに触れること自体**の扱い
- **E2EE であることが何を免除し、何を免除しないか**
- P4 / P5 で、**利用者が第三者の通信のメタデータに触れる**状態をどう説明するか

### (3) 先行例の実際の扱い

以下が**日本で実際にどう扱われているか / いないか**を、推測ではなく事実で。

- **Tor の Relay / Exit Node を日本国内で運用している例**（あるなら、どういう立て付けか）
- **Winny 事件の争点**（最高裁判決の判示。**index の有無が争点だったのか、そうでないのか**）
- **Jami / SimpleX / Briar 等、P2P Messenger が日本で提供されている際の位置づけ**
- **WebRTC の TURN サーバーを提供している国内サービスの扱い**

> **注意**: v2 §20 は「Public Piracy File Index を作らない」ことで Winny を回避したと書いているが、
> **その回避が成立するかどうかがこの調査の要**。判決の実際の判示を確認すること。
> **企画書の主張を裏付ける方向に寄せない。**

### (4) 同意の取り方（P4 / P5 のみ）

v2 §14 の `Willingness` を、**法的に意味のある同意にするには何が要るか**。

- **既定 ON と既定 OFF で扱いが変わるか**
- **中継していることが本人に見える必要があるか**（量・相手数・進行中かどうか）
- **いつでも止められる必要があるか**
- 利用規約でどこまで移転できるのか / できないのか

## 調べるときの制約

- **一次情報を使う。**総務省・e-Gov 法令検索・裁判所の判決文。**まとめ記事・ブログを根拠にしない**
- **「グレー」で終わらせない。**何が確定していて何が未確定かを分けて書く
- **企画を通す方向に寄せない。**「P5 は難しい」という結論のほうが有用
- **分からないものは分からないと書く。**埋めない
- **法律判断そのものは書かない。**これは論点整理であって、専門家レビューの代わりではない
  （v2 §20 も専門家レビューを前提にしている）
