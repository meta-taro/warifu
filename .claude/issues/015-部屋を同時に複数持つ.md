## どこから来たか

2026-09-08。オーナーが「1 対 1 と 1 対 N がはっきりしない」と言った所。

> **１たい１、１たいNがはっきりしないと**
>
> LINE ですと ＋ で部屋に参加させられるんですよね。こっちのほうが人は分かりやすい。

**画面の言葉は「部屋」にした**（**D64**）。だが**部屋は 1 つしか持てない。**

## 何が足りないか

`apps/desktop/src-tauri/src/lib.rs` の `Bridge` ——

```rust
conference: Arc<Mutex<Option<Conference>>>,
```

**`Option` である。**いま居られる部屋は 1 つだけ。

そのため ——

- 「air と 2 人で話しながら、3 人の部屋にも居る」ができない
- 部屋を移ると、**前の部屋の会話が消える**（履歴を持っていないため）
- 連絡帳で相手を選んでも、**その相手との部屋を開く**ことにならない

**「相手を選ぶ ＝ その人との部屋を開く」**が成り立たないので、
1 対 1 と 1 対 N が、人から見て区別できない。

## 決めること

1. **同時にいくつ持てるか。**上限を置くか（経路と CPU の実測が要る・`issues/005`）
2. **どの部屋の会話を画面に出すか。**選んだ部屋だけか、混ぜるか
   （**混ぜない**が筋。混ぜると相手ごとの会話に見えない）
3. **会話をどこに持つか。**いまは閉じれば消える。部屋ごとに分けるなら、
   **どこに置くかを決める必要がある**（`issues/010` の履歴と同じ話）
4. **通話（音声・映像）は 1 つの部屋だけか。**複数の部屋で同時に鳴らすのは、
   人が聞き分けられない
5. **`＋` で人を足したとき、部屋の id はどうなるか。**
   同じ部屋のままか、新しい部屋になるか（LINE は新しい部屋になる）

## 大きさ

**中継（D13）と並ぶ。**経路（`Node` / `outbound`）と会議（`Conference`）の
持ち方が変わるので、`warifu-app` から画面まで通しで直すことになる。

## 止めるべき条件

- **部屋ごとに別の身元を持ち始めたら止める。**身元は端末の鍵ひとつ（**D42**）
- **履歴をどこかに預ける形になったら止める。**それは D13 / D7 の話である

## 決めたこと（2026-09-08・オーナー承認）

| 決めること | 決め | なぜ |
|---|---|---|
| **同時にいくつ** | **上限を置かない**（部屋ごとの定員 12 はそのまま） | 部屋は軽い。重いのは通話 |
| **どの部屋の会話を出すか** | **選んだ部屋だけ。混ぜない** | 混ぜると、相手ごとの会話に見えない |
| **会話をどこに持つか** | **部屋ごとに分ける。閉じれば消える** | 履歴は別の話（`issues/010`） |
| **通話は何部屋** | **1 部屋だけ** | 複数で鳴らすと人が聞き分けられない |
| **`＋` で足したら** | **同じ部屋のまま** | 「1 対 1 と 1 対 N を別物にしない」（**D64**）に素直 |

### 段 1 で分かったこと

**思ったより収まった。**`Notice` は前から部屋の id を持っていたので、
届いた知らせは**振り分けるだけ**で済んだ。`outbound` は相手ごとなので触っていない
（1 本の経路が複数の部屋を運べる）。

変わったのは **送る側**である —— いままで**全員へ配っていた**ものを、
**その部屋に居る相手だけ**へ送るようにした。部屋を複数持つと、
全員へ配れば**別の部屋の人にも届く。**
