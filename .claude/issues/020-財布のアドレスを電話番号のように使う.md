# 芯になる置き換え

**アドレスが指すものを「居場所」から「公開鍵 ＋ 預かり所」へ変える。**

```
✗ アドレス → いまどこに居るか（IP と口）
     → 永久に公開される。口は変わる（2026-09-17 に D115 で直した所）。**誰でも叩ける**（D31 が崩れる）

○ アドレス → **公開鍵 ＋ 預かり所**
     → **居場所は出ない。**公開鍵は秘密でなく、**変わらない**ので書き直しも要らない
```

**叩かれるのではなく、手紙が置かれる。**

```
1. 相手はアドレスしか知らない
2. 台帳を読む: 「BSV 鍵 X ＝ 警符の公開鍵 Y ＋ 預かり所 Z」（**X の秘密鍵で署名済み**）
3. **Y へ封をして Z に置く**        ← Z は中身も差出人も読めない（**D69**）
4. 本人が Z から取って開ける        ← **頼んでいないものは注意を奪わない**（**D31** を保つ）
5. 話したければ**封の中で割符を 1 本返す** → 以後はいつもの直接の会話
```

# 危ないこと（**重い順**）

## 1. **この木は、まだ金を持つ段ではない**

**今日 1 日で、AI 側の間違いが 5 件出た。**うち 4 件は他の機械が測って見つけた。

```
「音だけ塞いで、文言だけ『送っていません』に変えた」   ← **塞げていないのに、そう書いた**
```

**会話の不具合は「届かない」で済む。金の不具合は「消える」。**
**同じ密度で間違えている木に、金を載せてはいけない。**

**→ 段 1（署名した紐づけ・秘密鍵を持たない形）から始める理由がこれである。**

## 2. **置き方の癖が「0600 で終わり」になっている**

```
seed              **平文**・0600
issued.tsv        割符の片割れ・0600
rejoin.tsv        割符の片割れ・0600
room-secret.tsv   部屋の合言葉・0600

crates/warifu-vault/src/lib.rs:999
    #[cfg(not(unix))]
    fn ensure_private(_path: &Path) -> Result<(), Error> { Ok(()) }   ← **Windows では見ていない**
```

**会話の身元なら妥当。お金なら失格。**
**同じ癖で財布を置くと、PC を盗られた時点で金が消える。**

**→ 財布の鍵は「合言葉で暗号化して置く」。0600 だけにしない。**

## 3. **紐づけは公開で、永久に消せない**

**チェーン解析 ＋ 会話の身元 = 誰と話しているかが推測されうる。**
**on-chain は取り消せない。**

**→ 逃げ道は D42 の導出。**

```
Personal（いまの身元）        紐づけない。手渡しの割符だけ
**公開用の身元（別 Profile）**  ← **こちらだけ財布に紐づける**
```

**種は同じ、鍵は別。**「電話番号として出す顔」と「私的な顔」を分ける。**いまの作りのままできる。**

## 4. **公開アドレスは、戸口の前提を外す**

**D31 の spam 対策は「招待経由でしか繋がれない」ことに立っている。**
**アドレスを知れば誰でも手紙を置ける**なら、そこが開く。

**→ 手紙は預かり所に置かれるだけで、叩かれはしない**（注意は奪われない）。
**→ さらに支払いを添えさせる**（段 3）。

**ただし、払えない人が届かなくなる。**——**それは排除である。**
**「初回だけ」「額を極小に」で緩められるが、原理として残る。**

## 5. **預かり所を常設すると、サーバになる**

**電話番号として使うなら、預かり所は常に居る必要がある。**
**D70 は「相手が起動していない間」の想定で、常設を考えていない。**

**そして預かり所は、封を開けられなくても「いつ誰あてに手紙が来たか」を見られる。**
**中継を避けた理由（D10）と同じものが、ここに戻ってくる。**

**→ これが、この計画でいちばん大きい未決である。**

## 6. **導出の道を間違えると、金が取り出せなくなる**

```
m/44'/236'/0'/0/0    SLIP-0044 の BSV
m/44'/0'/0'/0/0      Bitcoin と同じ道（**古い BSV ウォレットはこちらが多い**）
```

**どちらを選ぶかで、復元できるウォレットが変わる。**
**間違えると「入るが出せない」財布ができる。**

**→ 「どのウォレットで開けたいか」から決める。**両方出す手もある。

## 7. **自分の中で往復するだけの試験は、間違っていても通る**

```
✗ 生成 → 語を出す → 自分で復元 → 同じアドレス
     → **「自分の規則で一貫している」しか言っていない。**他のウォレットでは開けない

○ **BIP39 / BIP32 の公式テストベクタと突き合わせる**
     → 決まった語から、決まった鍵とアドレスが出る
     → **これで初めて「他のウォレットで開ける」が言える**
```

**2026-09-17 の `なし` と `0` とまったく同じ形である**——
**区別できない試験を合格にすると、気づくのは金を失った後になる。**

**→ 試験は 2 段。段 1（テストベクタ）の無い段 2 は意味がない。**

## 8. **記録に落ちる道が、いくらでも在る**

**この木は記録を厚く書く癖がある**（それは良いことだが）。
**`記録!` を 1 行、変数を間違えて書けば、語がそのまま出る。**

**→ 今日 D118 でやったのと同じ形にする** ——
**`Debug` が中身を出さない型に入れる。**「気をつける」では必ず漏れる。

## 9. **法の整理が済んでいない**

**この木には前例が在る。**D111 ——

> **D7（中継）に踏み込まない。**主催が配り直す形は、**法的整理が済むまで採れない。**

**金を動かす口を持つと、国によっては別の規制に入る。**
**中継を止めたのと同じ理由で、ここも止まるべき可能性がある。**
**→ これは AI が判断する所ではない。人が確かめる。**

## 10. **トークンで部屋を絞ると、部屋が金融商品に近づく**

**「持っている人だけの部屋」は、部屋の性質を変える。**
**集まる人も、狙う人も変わる。**——**それが望むものかは、事業の判断である。**
