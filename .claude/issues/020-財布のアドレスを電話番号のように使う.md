# 芯になる置き換え

**アドレスが指すものを「居場所」から「公開鍵 ＋ 預かり所」へ変える。**

```
✗ アドレス → いまどこに居るか（IP と口）
     → 永久に公開される。口は変わる（2026-09-17 に D115 で直した所）。**誰でも叩ける**（D31 が崩れる）

○ アドレス → **公開鍵 ＋ 預かり所**
     → **居場所は出ない。**公開鍵は秘密でなく、**変わらない**ので書き直しも要らない
```

**叩かれるのではなく、手紙が置かれる。**

```
1. 相手はアドレスしか知らない
2. 台帳を読む: 「BSV 鍵 X ＝ 警符の公開鍵 Y ＋ 預かり所 Z」（**X の秘密鍵で署名済み**）
3. **Y へ封をして Z に置く**        ← Z は中身も差出人も読めない（**D69**）
4. 本人が Z から取って開ける        ← **頼んでいないものは注意を奪わない**（**D31** を保つ）
5. 話したければ**封の中で割符を 1 本返す** → 以後はいつもの直接の会話
```

# 危ないこと（**重い順**）

## 1. **この木は、まだ金を持つ段ではない**

**今日 1 日で、AI 側の間違いが 5 件出た。**うち 4 件は他の機械が測って見つけた。

```
「音だけ塞いで、文言だけ『送っていません』に変えた」   ← **塞げていないのに、そう書いた**
```

**会話の不具合は「届かない」で済む。金の不具合は「消える」。**
**同じ密度で間違えている木に、金を載せてはいけない。**

**→ 段 1（署名した紐づけ・秘密鍵を持たない形）から始める理由がこれである。**

## 2. **置き方の癖が「0600 で終わり」になっている**

```
seed              **平文**・0600
issued.tsv        割符の片割れ・0600
rejoin.tsv        割符の片割れ・0600
room-secret.tsv   部屋の合言葉・0600

crates/warifu-vault/src/lib.rs:999
    #[cfg(not(unix))]
    fn ensure_private(_path: &Path) -> Result<(), Error> { Ok(()) }   ← **Windows では見ていない**
```

**会話の身元なら妥当。お金なら失格。**
**同じ癖で財布を置くと、PC を盗られた時点で金が消える。**

**→ 財布の鍵は「合言葉で暗号化して置く」。0600 だけにしない。**

## 3. **紐づけは公開で、永久に消せない**

**チェーン解析 ＋ 会話の身元 = 誰と話しているかが推測されうる。**
**on-chain は取り消せない。**

**→ 逃げ道は D42 の導出。**

```
Personal（いまの身元）        紐づけない。手渡しの割符だけ
**公開用の身元（別 Profile）**  ← **こちらだけ財布に紐づける**
```

**種は同じ、鍵は別。**「電話番号として出す顔」と「私的な顔」を分ける。**いまの作りのままできる。**

## 4. **公開アドレスは、戸口の前提を外す**

**D31 の spam 対策は「招待経由でしか繋がれない」ことに立っている。**
**アドレスを知れば誰でも手紙を置ける**なら、そこが開く。

**→ 手紙は預かり所に置かれるだけで、叩かれはしない**（注意は奪われない）。
**→ さらに支払いを添えさせる**（段 3）。

**ただし、払えない人が届かなくなる。**——**それは排除である。**
**「初回だけ」「額を極小に」で緩められるが、原理として残る。**

## 5. **預かり所を常設すると、サーバになる**

**電話番号として使うなら、預かり所は常に居る必要がある。**
**D70 は「相手が起動していない間」の想定で、常設を考えていない。**

**そして預かり所は、封を開けられなくても「いつ誰あてに手紙が来たか」を見られる。**
**中継を避けた理由（D10）と同じものが、ここに戻ってくる。**

**→ これが、この計画でいちばん大きい未決である。**

## 6. **導出の道を間違えると、金が取り出せなくなる**

```
m/44'/236'/0'/0/0    SLIP-0044 の BSV
m/44'/0'/0'/0/0      Bitcoin と同じ道（**古い BSV ウォレットはこちらが多い**）
```

**どちらを選ぶかで、復元できるウォレットが変わる。**
**間違えると「入るが出せない」財布ができる。**

**→ 「どのウォレットで開けたいか」から決める。**両方出す手もある。

## 7. **自分の中で往復するだけの試験は、間違っていても通る**

```
✗ 生成 → 語を出す → 自分で復元 → 同じアドレス
     → **「自分の規則で一貫している」しか言っていない。**他のウォレットでは開けない

○ **BIP39 / BIP32 の公式テストベクタと突き合わせる**
     → 決まった語から、決まった鍵とアドレスが出る
     → **これで初めて「他のウォレットで開ける」が言える**
```

**2026-09-17 の `なし` と `0` とまったく同じ形である**——
**区別できない試験を合格にすると、気づくのは金を失った後になる。**

**→ 試験は 2 段。段 1（テストベクタ）の無い段 2 は意味がない。**

## 8. **記録に落ちる道が、いくらでも在る**

**この木は記録を厚く書く癖がある**（それは良いことだが）。
**`記録!` を 1 行、変数を間違えて書けば、語がそのまま出る。**

**→ 今日 D118 でやったのと同じ形にする** ——
**`Debug` が中身を出さない型に入れる。**「気をつける」では必ず漏れる。

## 9. **法の整理が済んでいない**

**この木には前例が在る。**D111 ——

> **D7（中継）に踏み込まない。**主催が配り直す形は、**法的整理が済むまで採れない。**

**金を動かす口を持つと、国によっては別の規制に入る。**
**中継を止めたのと同じ理由で、ここも止まるべき可能性がある。**
**→ これは AI が判断する所ではない。人が確かめる。**

## 10. **トークンで部屋を絞ると、部屋が金融商品に近づく**

**「持っている人だけの部屋」は、部屋の性質を変える。**


## **諦めるもの —— 「アドレスから引く」は成り立たない**

**元の望みはこうだった。**

> **ウォレットアドレスを会議キーや電話番号のように使いたい**

**ノードに触らないなら、アドレスは「どこに居るか」を教えられない。**

**だから、こうなる。**

| | |
|---|---|
| ✗ **引くための番号** | アドレスだけ知って、そこから相手を探す ——**台帳が要る** |
| ○ **変わらない名前** | **鍵と一緒に渡す。**中に入っている名前として使う |

**誰でも引ける所が無ければ、誰も届けられない。**
**→ そこを望むなら、台帳（＝サーバか chain）を飲む判断が別に要る。**

## **残るもの —— それでも 3 つ成立する**

### 1. **変わらない名前**（鍵が変わっても、同じ人だと分かる）

**警符の身元は端末ごとに導く**（D42）。**端末を替えれば鍵が変わる。**
**財布の鍵を上に置けば、その上で「同じ人」が続く。**

```
「BSV 鍵 X の持ち主は、警符の鍵 Y である」   ← X で署名
（端末を替える）
「BSV 鍵 X の持ち主は、警符の鍵 Y' である」  ← **X で署名。同じ人だと分かる**
```

**台帳は要らない。**署名が手元で検められる。

### 2. **払う相手が、話している相手と同じだと確かめられる**

**これが一番の価値で、しかも一番安い。**
**警符は「この人は X の持ち主だ」と言うだけ。払うのは人が自分の財布でやる。**

### 3. **トークンの配布 —— 名簿がそのまま宛先一覧になる**

```
警符（または札を持つプラグイン）  部屋に居る人の**アドレスを並べて出す**
人                                **自分の財布で、自分の選んだノードへ投げる**
```

**「どこにブロキャスするかは個人の勝手」が、そのまま形になる。**
**警符は一度も送金に触らない。**

# 追記 3（2026-09-18）—— **鍵の生成に BSV のやり方を採る。使い捨てのアドレスを出す**

オーナー ——

> **着金はできちゃうけど、そんなことを公表もしません。**
> **使い捨ての電話番号のようにウォレットアドレスを発行できます。**
>
> **ただキー生成に BSV のアルゴリズムを採用するだけです**

## これが効く理由 —— **BIP32 は「1 つの種から無限の鍵」である**

**いまの警符は、身元を HKDF で導いている**（`key.rs`・**D42**）。
**BIP32 に替えると、同じ性質の上に「番号で数えられる木」が乗る。**

```
語 12 個（**控えるのは 1 つだけ**）
  → m/44'/236'/0'/0/**0**   相手 A 用
  → m/44'/236'/0'/0/**1**   相手 B 用
  → m/44'/236'/0'/0/**2**   この部屋用
  …
```

**使い捨ての電話番号になる。**そして ——

### **privacy が上がる**（これは副産物ではなく、本筋かもしれない）

**いまは端末に 1 つの鍵なので、どの部屋でも同じ鍵で出ている。**
**相手同士が突き合わせれば、別の部屋のあなたが同じ人だと分かる。**

**相手ごとに鍵を出せば、それができなくなる。**
**「1 本＝1 人」（D12）の上に「1 人＝1 鍵」が乗る形**である。

## 壁 —— **曲線が違う**

```
BSV        secp256k1
警符・iroh  **Ed25519**   ← **経路の身元はこれ。iroh の NodeId がそれ自体 Ed25519 の公開鍵**
```

**secp256k1 の鍵を、そのまま経路の身元にはできない。**

**そして同じ 32 バイトを両方の秘密鍵に使ってはいけない**
（アルゴリズムをまたぐ鍵の再利用。片方の弱点が他方へ渡る）。

### 解き方 —— **1 つの種から、別々に導く**

```
語 12 個
  ├─ m/44'/236'/0'/0/n              → secp256k1 → **BSV アドレス n**
  │                                     （**他のウォレットで開ける。着金もできる**）
  └─ **BIP-85**（m/83696968'/…/n）  → 32 バイトの子エントロピー
                                      → **Ed25519 の種 → 警符の鍵 n**
        ＋ **BSV 鍵 n で「この Ed25519 鍵は私のものだ」と署名**
```

**BIP-85 は、まさにこれのために在る規格**である（1 つの BIP39 の種から、
他の用途の子エントロピーを導く）。**自前で道を発明しない。**

| | |
|---|---|
| **控えは 1 つ** | 語 12 個で、財布も警符の身元も戻る |
| **他のウォレットで開ける** | BSV 側は**素の BIP44**。余計な導出を挟まない |
| **鍵は別** | 片方が漏れても、もう片方は導けない |
| **同じ人だと言える** | 署名で紐づく（追記 2 の「変わらない名前」） |

# **「公表しない」は「価値が入らない」ではない**（**いちばん大事な注意**）

**着金できる鍵を持った瞬間、種は財布の控えになる。**
**公表しなくても、そうなる。**

## 1. **来るものは来る**

**Bitcoin 系では、見知らぬアドレスへ極少額を送る行為が実際に行われている**
（塵を送って、その動きを見る手口）。**アドレスが在れば、入りうる。**

**→ 種を失うと、金を失う。****「アルゴリズムだけ」と言っていても、そうなる。**
**→ 画面は、そう言わなければならない** ——
**「この語は財布の控えでもあります」**と。**言わないのは嘘である。**

## 2. **一度でも使うと、使い捨てが繋がる**

**警符は送金しないので、使い捨ては保たれる**（動かさなければ、何も繋がらない）。

**だが人が後で、その種を財布へ入れて残高をまとめたら** ——
**まとめた取引が、全部のアドレスを 1 つに繋ぐ。**
**＝ 別の部屋で使っていた身元が、全部同じ人だと分かる。**

**→ これは警符の外で起きるが、警符が原因を作る。**
**→ 画面で言う。「まとめると、分けていた身元が繋がります」**

## 3. **私たちは今日、鍵を public な issue に貼っている**

```
#37 / #24 に、割符の鍵をそのまま貼って試験した（今日 5 本以上）
```

**もし鍵がアドレスを含む形になったら、それは「ウォレットアドレスを公開に貼る」ことになる。**
**試験のやり方を変える必要がある。**

**→ 鍵にアドレスを載せるかどうかは、そこから決める。**
**→ 載せないなら、紐づけは「封の中」「部屋の中」だけで渡す**（追記 2 の形）。

# 追記 4（2026-09-18）—— **形は核に、網は外に**

オーナー ——

> **そのうちマイナー API みたいな設定を登録したら、そのうち送金着金できちゃう
> みたいな展開はありえます。普及したものが使われる可能性があるので**
>
> **ただオリジナルのキーで運用するより夢もあります。**
> **NFT とかやり取りできたり。ビッグブロックにスクリプトを入れて仮想空間を作ったり**

## いま決めるべきことは 1 つに絞れる

```
**形（鍵の導き方・アドレスの書き方・署名の検め方）** → **核に入れる**（オフライン・依存が増えない）
**網（送金・台帳を読む・マイナー API）**             → **全部外**（人が登録したときだけ動く）
```

**この線を引いておけば、挙げられた展開は全部あとから乗る。**
**そして核は書き換えずに済む。**

| やりたいこと | 要るもの | 核を触るか |
|---|---|---|
| 送金・着金 | マイナー API の登録（人が入れる） | **触らない** |
| **NFT のやり取り** | **署名したデータを 2 人の間で運ぶ** | **触らない。今すでにできる** |
| ブロックのスクリプトで仮想空間 | 台帳を読むプラグイン | **触らない** |

## **NFT は、いまの警符でもう運べる**

**警符は「確かめた相手との間で、封をしたデータを運ぶ道」である。**
**所有の証しは署名したデータにすぎない。**——**新しい仕組みは要らない。**

```
封（D69）で相手の公開鍵へ封をして渡す   ← **もう在る**
差出人は封から分からない（D69）         ← **もう在る**
相手が本人であることは経路が確かめる     ← **もう在る**
```

**足りないのは「それが本物だと台帳で確かめる」所だけ**で、**それは外の仕事**である。

## **仮想空間の入場は、D118 がそのまま使える**（今日作ったもの）

**部屋に入れるかは、合言葉の証しで決まる**（**D118**・2026-09-17）。

```
プラグイン（台帳を読む）  「この鍵の持ち主は条件を満たす」→ **合言葉を渡す**
警符（本体）              **合言葉の証しで通す。台帳を一度も見ない**
```

**「トークンを持つ人だけの部屋」が、核を触らずに作れる。**
**新しい入場の仕組みを足す必要が無い。**——**今日の作りが、そのまま土台になっている。**

## **形を採ることの代償**（正直に）

### 1. **身元の導き方は、一度決めたら戻れない**

**みんなの身元がそこから出るので、後から道を変えると全員の身元が変わる。**

**→ だから公式テストベクタ（BIP32/39/44/85）が要る。**
**→ 道（`236'` か `0'` か）も、最初に決める。**

### 2. **ECDSA には、Ed25519 に無い足元の穴がある**

```
Ed25519    署名は決定的。**同じものに何度署名しても同じ**
ECDSA      **署名ごとに違う乱数（nonce）が要る。**
           **一度でも同じ nonce を使うと、秘密鍵が割れる**
```

**これは実際に何度も起きている事故である**（乱数が弱い実装で、鍵が復元された）。

**→ 署名するなら RFC 6979（決定的 ECDSA）**を使う。乱数に頼らない。
**→ そして、この形では出番が少ない** ——
**経路の署名は Ed25519 のまま**で、**secp256k1 で署名するのは「紐づけ」1 回だけ**である。
**穴を踏む回数を、設計で減らしてある。**

### 3. **「普及したもの」は、攻める側にも普及している**

**財布を探す道具も、塵を送る手口も、すでに在る。**
**標準の形を採ると、そういう道具の対象になる**（追記 3 の A / B）。
