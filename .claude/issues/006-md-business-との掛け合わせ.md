## 作るもの

**`file.*` Intent。**warifu の E2EE 経路でバイト列を相手へ渡すだけの口。

md-business の文書（`.md` / `.tsv`）を、Google ドライブにも OneDrive にも置かずに、
相手の端末へ直接届ける。

---

## 依存の向きを間違えない（D11）

```
md-business  ──依存──▶  warifu
     （文書）              （経路）
```

**この向きだけ。逆は無い。**

- **warifu は md-business を知らない。**`file.*` は「バイト列 + MIME タイプ + ファイル名」しか運ばない
- **warifu は中身を解釈しない。**`.md` だから特別扱い、はやらない
- **warifu 単体で完結する。**md-business が無くても warifu は動く

原案 §12「md-business を必須 Dependency にしない」を守るための制約であり、
**利便のために崩してよい制約ではない。**一度でも中身を見に行くと、
warifu は「文書ツールの付属品」になり、他の何にも使えなくなる。

---

## なぜこれで置き換わるのか

| 置き換わるもの | 何が担うか |
|---|---|
| Google ドライブ / OneDrive | **md-business の文書 + warifu の直接転送**（保管はローカル、共有は P2P） |
| Google ドキュメント / Word / Excel | **md-business。warifu は何も担わない** |
| Teams / Meet / Zoom | **warifu の会議**（`005`） |
| アカウント / テナント / 招待 | **不要。鍵が Identity**（`003`） |

**warifu が担うのは経路だけです。**文書の側は md-business の仕事であり、
このリポジトリでは作りません。

## 範囲

### 含む

- `file.offer` / `file.accept` / `file.reject` / `file.chunk` / `file.complete`
- **受信側が明示的に受け入れるまで、バイト列が 1 バイトも流れない**
- ハッシュ照合（届いたものが送ったものと同じか）
- 転送の中断と再開

### 含まない

- **同期**（双方向・競合解決）。まず片方向の転送で足りるか確かめる
- 文書の中身に関わる一切（プレビュー・変換・検索・差分）
- md-business 側の実装（**このリポジトリの仕事ではない**）

---

## D5 を `file.*` にも効かせる

受信したファイルは**データであって命令ではない**（D5）。

- **受信したファイル名でパスを組み立てない**（`../` / 絶対パス / 予約名 / 長さ）
- **受信した MIME タイプを信用しない**（拡張子と一致しなくても、warifu は判断しない。**保存するだけ**）
- **自動で開かない。**開くかどうかは人が決める
- **受信した中身をモデルに渡さない**（warifu の層では、そもそも中身を読まない）

## 完了条件

- [ ] 別々の物理マシン間で `.md` と `.tsv` が転送でき、ハッシュが一致する
- [ ] **どのクラウドにもアカウントを作らずに**転送できた記録がある
- [ ] 受信側が拒否したとき、バイト列が流れていないことをテストで確認している
- [ ] 悪意あるファイル名（`../` を含む等）でパスが外へ出ないことをテストで確認している
- [ ] 100MB 級で転送が完了する（メモリに全部載せていない）
- [ ] 転送を中断して再開できる
- [ ] **受け取った文書を md-business で実際に開いて、読めることを人が確認した記録がある**

**最後の 1 つは人が実際にやらないと書けません。**
AI に代わりに答えさせないでください（baseline §19 / §29）。

---

## md-business 側が必要になったら

**このリポジトリで md-business のコードを書かないこと。**

必要が出た時点で **md-business 側に Issue を立てる**（baseline §27 / §14）。
warifu 側から提供するのは「`file.*` の仕様」までで、
それを呼ぶかどうかは md-business 側の判断です。
