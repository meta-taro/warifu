## M1 で作ったもの

| ファイル | 中身 |
|---|---|
| `crates/warifu-core/src/key.rs` | シード → Profile → Device の**決定的**な鍵導出（HKDF-SHA512 / Ed25519） |
| `crates/warifu-core/src/tally.rs` | 割符の発行・受諾・照合。**秘密そのものを返送させない**（証だけを返す） |
| `crates/warifu-core/src/revocation.rs` | 失効の名簿。**取り消せない**（降ろせると鍵を盗った側が降ろせる） |
| `crates/warifu-core/src/base32.rs` | RFC 4648 base32。**同じバイト列に複数の表記を許さない** |
| `crates/warifu-core/src/error.rs` | 失敗の種類。秘密は入らない |

**ネットワークのコードは 1 行も入っていない。**割符は QR・紙・口頭でも成立する。

## M2 で作ったもの

| ファイル | 中身 |
|---|---|
| `crates/warifu-net/src/node.rs` | 結び目と 1 本の経路。**端末の Ed25519 鍵をそのまま QUIC の鍵にする** |
| `crates/warifu-net/src/address.rs` | 宛先（公開鍵＋今つながる場所）。`WARIFU1-` + base32 の 1 通りの表記 |
| `crates/warifu-net/src/error.rs` | 失敗の種類。**下の層の理由を捨てない**（`Network { doing, cause }`） |

この層が引き受けるのは 2 つだけ。**相手が本当にその公開鍵の持ち主か**を繋がった時点で確かめること、
**失効している相手を通さない**こと（呼ぶ側・受ける側の双方で見る）。
暗号も NAT 越えも自前では書いていない（原案 §8）。

M1 側の変更は 2 つ。`Device::secret_key_bytes()`（経路が同じ鍵を使うための口）と、
`base32` の公開（**warifu が外に出す文字列を割符と宛先で 1 種類に揃えるため**）。
